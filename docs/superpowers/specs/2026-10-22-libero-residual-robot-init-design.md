# Residual RL on procedurally shifted robot initial states: design

Date: 2026-10-22. Milestone 2 of the out-of-distribution residual programme. Predecessors: `docs/superpowers/specs/2026-10-21-libero-prior-design.md` (the selected prior, `docs/libero-prior.md`) and `docs/dice-rl-reproduction.md` (the released recipe reproduced on Tool Hang). Research grounding: `docs/research/2026-10-21-residuals-under-distribution-shift.md`, `docs/research/2026-10-21-dice-rl-paper-dive.md`.

## Intent

Train the DICE-RL noise-space residual over the frozen 20-demo LIBERO prior with every training episode starting from a procedurally shifted robot initial pose, and measure whether the residual gives success on the held-out LIBERO-Plus robot-init variants that the frozen prior does not have. This is the first measurement of the programme's thesis (a residual trained on a wide shift distribution over a frozen prior is a cheaper route to out-of-distribution robustness than post-training the prior), which the literature leaves untested. One axis only: robot initial pose. Layout shifts are the next wave on the same machinery.

## Goals

- A soft-reset path for the LIBERO wrapper, gated for correctness and measured for latency, because the current hard reset (model rebuild, about 17 s per batch) would dominate RL wall time.
- A procedural robot-init shift in the wrapper: joint offsets added to a stored initial state before it is loaded, with a magnitude the training process ramps, and a validity check that rejects colliding or out-of-range starts.
- The released DICE-RL image fine-tune recipe, run unchanged except for the two agreed departures (residual conditioned on the base action; shifted training starts with a ramp), from the selected prior, with the 20 demos as offline data.
- Held-out evaluation on the LIBERO-Plus robot-init variants of this task (42 variants × 50 stored states, never used in training) with the canonical 50 states as the in-distribution check, for the frozen prior and for residual checkpoints.
- A measured compute projection before the long run.

## Non-goals and anti-goals

- No layout, camera, lighting or background shifts. No bound on the residual magnitude (deferred by decision). No changes to the critic's inputs beyond what the released image recipe does.
- No multitask, no second task, no second seed in this milestone. The control run (same recipe on canonical starts) is decided after this run's result.
- No edits to vendored DICE-RL algorithm code (`agent/`, `model/`, `util/`, `script/run.py`, `script/eval_rl_checkpoint.py`, `cfg/robomimic/`); the ramp is driven from a subclass in a new file. No edits to `.cache/lerobot`, `script/lingbot_*`, the reproduction or LIBERO venvs' pins.
- Anti-goal: a result that cannot be attributed. The training distribution, the held-out set and every evaluation's seeds and env count are recorded in each summary, and the in-distribution check runs alongside every held-out number so a gain on shifts bought with a loss on canonical starts is visible.
- Anti-goal: a residual that learns a pose-independent offset. The success-versus-shift-magnitude curve on fresh procedural seeds and the per-variant breakdown on LIBERO-Plus are reported so that a flat gain across magnitudes is distinguishable from a shift-dependent correction.

## Facts the design rests on (measured 2026-10-22)

- The task's flattened MuJoCo state has 47 entries: time (1), qpos (24), qvel (22). qpos indices 0–6 are the seven Panda joints (state entries 1–7), 7–8 the gripper fingers, then the two mugs' free joints (7 each) and the microwave hinge.
- LIBERO-Plus robot-init variants 640–681 of `libero_10` (42 variants) do not store shifted states: their stored init files are identical to the canonical ones (checked 2026-10-22 on variants 640, 650, 681). The shift lives in the variant's robot class (`MountedPandaN.init_qpos`, a per-variant 7-vector with l2 offset 0.1–0.5 rad from the canonical pose), which robosuite loads into the joints at reset and which the OSC controller takes as its initial joint configuration (the nullspace target). The earlier LingBot evaluation therefore ran those variants with `init_states=False` (objects sampled at reset). The robosuite controller exposes `update_initial_joints(joints)` for the same effect after a state load.
- The selected prior: `state_100.pt` of run `2026-10-22_10-11-34_42` (20 demos, 9,400 updates), 0.52 / 0.47 / 0.38 on three seed pairs, pooled 0.457 ± 0.029; held-out evaluations carry about ±5 points per 100 episodes and about 7 points of spread between seed pairs, so comparisons use 300 episodes.
- Reset-to-reset render jitter is up to 4% on the wrist camera; demo replay from the same stored state reaches first success between steps 301 and 326.

## Soft reset (gate A, before anything else)

`make_libero_env` gains `hard_reset` (default `True`, so the pretraining and prior-evaluation paths are unchanged), passed to `OffScreenRenderEnv`; the `libero_image` wrapper block gains a `hard_reset` key that the factory's libero branch pops before constructing the wrapper and passes to `make_libero_env` (the factory currently calls `make_libero_env(id)` with no options and forwards every wrapper key to the wrapper constructor, so both edits are in the allowed libero branch). The RL and residual-evaluation configs set `hard_reset: false`. With `hard_reset=False` robosuite keeps the compiled model and resets the simulation state; `set_init_state` then loads the full stored state as before.

Gate A checks, each written to `gate_a.json` by `script/dicerl_libero_gate_a.py` and recorded in `docs/libero-residual.md`:

1. Demo 0 replays to success from its stored state after a soft reset (the gate-0 replay, now with `hard_reset=False`).
2. Equivalence: for stored states 0, 17 and 42, the first wrapper observation (normalised state and both images) after `reset(options={"init_state": s})` agrees (proprioception to 1e-4, images to the measured reset jitter, below 0.05 mean absolute difference) whether the env was soft- or hard-reset, and whether the reset follows a fresh build or 20 completed episodes of random actions. This is what guarantees soft resets do not carry state across episodes. If the proprioception disagrees by more than 1e-3 on any state, soft reset is rejected: the recipe falls back to hard resets and the budget is rebuilt from the measured hard-reset latency and reported before launch.
3. Drift: 200 consecutive soft resets to state 0 give the same post-settle proprioception to 1e-4.
5. Controller reference: after a soft reset and a load of a shifted state followed by `update_initial_joints`, 50 no-op steps leave the arm within 2e-2 rad of the loaded joints (the nullspace pull targets the shifted pose); without the update the drift toward the canonical pose is recorded for comparison.
4. Latency: mean reset time with soft and hard resets on one env, and env steps per second through `make_async` with 8 envs over 20 full episodes including resets, both measured.

## Procedural robot-init shift

Implemented in `env/gym_utils/wrapper/libero_image.py` (the wrapper) and a small helper module `env/gym_utils/wrapper/libero_shift.py`:

- `shift_state(state, offset, joint_slice=slice(1, 8)) -> np.ndarray`: a copy of the stored state with the seven joint entries offset; velocities untouched (they are zero in stored states).
- `sample_offset(rng, magnitude) -> np.ndarray` (7,): a direction uniform on the sphere scaled by a norm drawn uniformly in [0, magnitude]; magnitude 0 returns zeros.
- `valid_start(env) -> bool` after `set_init_state` and `sim.forward()`: every Panda joint inside its model range with a 0.02 rad margin, and no contact pair in `sim.data.contact[:ncon]` that involves a robot or gripper geom and a non-gripper geom (finger-to-finger contact of the open gripper is allowed). The implementer confirms the geom-name test against the model's geom names at gate B.
- Wrapper: a `shift` attribute (`{"magnitude": float, "seed": int}` or `None`) and a method `set_shift(magnitude, seed)`; each worker gets its own seed (base seed plus worker index, delivered through `call_sync_arg`) so the eight workers draw different offset sequences. On every reset that draws a stored state (seeded or random), if `shift` is active the wrapper draws an offset with its own `np.random.RandomState([seed, reset_count])`, loads the shifted state, and runs `valid_start`; on failure it resamples up to 20 times and then falls back to the unshifted state, counting the rejection. A reset with an explicit `init_state` applies no shift unless the options also carry `shift: {"magnitude": m, "seed": s}`, in which case the same sampler and validity check run on the supplied state (this is how the evaluator produces the procedural curve with the training distribution's rejection rule). Whenever the loaded state's joints differ from the stored canonical joints (a shifted start or a held-out variant pose), the wrapper calls the robot controller's `update_initial_joints` with the loaded joint positions, so the OSC nullspace target follows the start pose exactly as it does for a LIBERO-Plus variant built from its own robot class. The wrapper exposes `shift_stats()` returning draws, rejections and fallbacks, reset per call.
- The vectorised env's `call_sync("set_shift", magnitude=m, seed=s)` (keyword arguments; the vendored `call_sync` takes `indices` positionally) reaches every worker, and `call_sync_arg` delivers per-worker seeds; the training workers hold `MultiStepFull` (the agent renames the wrapper), whose auto-reset goes through the wrapper's `reset()` with no options, which is the path that draws a shifted stored state during training.

Gate B (`script/dicerl_libero_gate_b.py`, written to `gate_b.json`): for magnitudes 0.1, 0.3, 0.5 and 0.6 rad, 200 draws each from the 50 stored states: rejection rate, fallback count, the realised l2 norm distribution, and the end-effector displacement distribution (from the post-settle proprioception) so the shift is described in both joint and task space; plus the frozen prior's success on 100 episodes at each magnitude with fresh seeds, which is the baseline curve the residual is compared against. Anything above a 20% rejection rate at 0.6 rad is reported before training (the sampler would then be concentrating on the easy part of the sphere).

## Training recipe

Base: `cfg/robomimic/finetune/square/ft_distill_residual_flow_unet_img.yaml` (the released image recipe for the medium-length robomimic task), copied to `brev/dicerl/cfg/libero/<task>/ft_distill_residual_flow_unet_img.yaml` with exactly these changes:

- paths: `base_policy_path` to the selected prior's `state_100.pt`, `normalization_path` and `expert_dataset.dataset_path` to `ph_pretrain_20`, `expert_dataset.max_n_episodes: 20`, log directory `libero-finetune`, W&B project `dice-rl-libero`, entity from the environment; `robomimic_env_cfg_path` removed;
- environment: `env.env_type: libero`, task name, `env.n_envs: 8` (the released image value), `max_episode_steps: 520`, wrappers `libero_image` (`normalization_path`, `shape_meta`, `success_steps_before_termination: 1`, `hard_reset: false`) then the unchanged `multi_step` block; `expert_dataset.success_steps_for_termination` repointed from the removed `robomimic_image` block to `libero_image`; `obs_dim: 8`, `shape_meta` as the prior's; `horizon_steps: 8`, `act_steps: 8`, `flow_steps: 10`, `noise_dim: 56` (not derived by the agent; action_dim × horizon);
- the agreed departure: `model.condition_residual_on_base_action: true` (the residual becomes r(s, a_base); the paper never ablates this switch);
- released recipe values kept as released for the image Square config except: `use_soft_q_filtering: true`, `always_retain_bc_loss_for_expert_data: false` (the two values the released Tool Hang training used and the reproduction validated), `q_underestimation_threshold: -0.55` (the validated Tool Hang state value; the nearest task by prior strength; a guess, recorded as such), `n_step: 3`, warm-ups as released for Square image (`replay_flow_warmup_steps: 3000`, `q_filtering_warmup_steps: 3000`), expert ratio 0.5 → 0.1 over 10,000 iterations, `gradient_steps: 20`, 10 critics, `max_q_min` with 16 samples for exploration and evaluation;
- `train.num_train_steps` large enough never to stop the run by itself; stopping is by the checkpoint schedule below; `save_freq: 1000`, `eval_freq: 1000`, `eval_n_envs: 10`, `num_eval_episodes: 30` as the released Square image config has them (300 episodes; the in-training evaluation lands on the canonical stored states through the wrapper's seed mapping, so it is the in-distribution curve).
- Base and carried values: the base is the Square image config; the only values carried from the validated Tool Hang state run are the two filter flags and the threshold, deliberately, because they are the three values whose effect the reproduction established; β, n-step, gradient steps, warm-ups and the expert ratio stay at the Square image values.
- Launcher: `brev/dicerl/finetune_libero.sh <task> [seed]` passing `--config-name=ft_distill_residual_flow_unet_img --config-dir=brev/dicerl/cfg/libero/<task>` to `script/run.py` in a box-local tmux session, following `brev/dicerl/finetune.sh`.

The ramp lives in `script/dicerl_libero_rl.py`: a subclass of `TrainDistillResidualFlowImgAgent` whose `update_networks(training_step)` (the vendored loop calls it `gradient_steps` times per iteration with the same `training_step`) sets the shift magnitude on the training vector env only when the magnitude changes, logs `shift/magnitude` and the summed worker rejection statistics to W&B once per iteration (guarded by the last logged step), then calls the parent. The schedule, in training iterations (one iteration = `n_envs × act_steps` = 64 env steps): magnitude 0 until the flow warm-up ends at iteration 3,000 (192k env steps), then linear from 0 to 0.6 rad over iterations 3,000–6,000 (192k env steps, the user's choice of a slow ramp so the residual has time to adjust at each magnitude), then 0.6 held. The run config names this subclass as `_target_` and carries `shift: {end_magnitude: 0.6, ramp_start: 3000, ramp_end: 6000, seed: 42}`. Evaluation envs never receive a shift.

Budget: checkpoints every 1,000 iterations; the run is stopped by the operator at 850k env steps (about 13,000 iterations, which leaves about 450k env steps at the full magnitude) or earlier if the held-out number has plateaued over three consecutive held-out evaluations after the ramp has ended; the wall-time projection from the smoke (gate C) is reported before launch, and anything projecting past 48 h is reported before launch rather than started.

Gate C (smoke): 200 iterations with the full config (cap through `train.num_train_steps`), measuring iterations per hour including resets and the in-training evaluation at iteration 0, plus one monitoring evaluation's wall time; the first checkpoint must load in the residual evaluator.

## Held-out evaluation

Two evaluators share the protocol code. `script/dicerl_libero_eval.py` (the frozen prior) gains `--states PATH` (an npz with `states` (N, 47) and `labels` (N,) strings) replacing the canonical init file, and `--shift M --shift-seed S` for the procedural curve (passed to the wrapper as the reset `shift` option, seed `S + episode index`, so the training sampler and validity rule apply). `script/dicerl_libero_rl_eval.py` (residual checkpoints) loads `model_step_<N>.pth` from the run directory with the run's `.hydra/config.yaml`, instantiates `cfg.model` (`DistillResidualRLImgModel`), loads `model_state_dict`, builds the augmented state the way the image agent does (the frozen prior's `extract_visual_features` on the observation, concatenated with proprioception; copied, since `agent/` is not editable), and selects actions with `get_exploration_action(..., num_samples=16, exploration_strategy="max_q_min", training_step=10**6)`; it takes the same `--states`, `--shift`, `--seeds`, `--envs` flags and writes the same `episodes.csv` and `summary.json` with the checkpoint's iteration recorded. `script/dicerl_libero_plus_states.py`, run once in the LeRobot environment on the box (the only place the LIBERO-Plus package is installed), exports the 42 robot-init variants' `init_qpos` vectors (from each variant's `MountedPandaN` robot class) and writes `$DICE_RL_DATA_DIR/libero/<task>/plus_robot_init.npz` with `states` = canonical stored states 0–6 with their seven joint entries replaced by each variant's pose (294 rows), `labels` `<variant>:<state index>`, and `init_qpos` (42, 7); the residual evaluator never imports LIBERO-Plus. The held-out set therefore has the variants' robot poses on the canonical stored layouts, which is the one-axis definition this milestone wants; the LIBERO-Plus benchmark itself samples layouts at reset, a documented difference.

Protocols, all with 8-step chunks, 520 steps, 25 envs, `max_q_min` with 16 samples for residual checkpoints (the released evaluation rule) and single-sample flow for the frozen prior (its own rule):

- Held-out (headline): variants 640–681, stored states 0–6 of each, 294 episodes, torch seed 0; the per-variant success is recorded.
- Monitoring during training: states 0–1 of each variant, 84 episodes, torch seed 0, every 2,000 iterations on the saved checkpoint, run by a watcher (`script/dicerl_libero_rl_watch.py`, sharing the pretraining watcher's functions with a `model_step_*.pth` pattern and the residual evaluator command) that appends to `heldout_sweep.json` and never stops the run. The watcher shares the GPU with training for the minutes each evaluation takes; this is accepted (the one-job rule means no second training job), and gate C's projection includes one monitoring evaluation per 2,000 iterations.
- In-distribution: the canonical 50 states × seeds 0, 1, 2 (150 episodes) on the final checkpoints; the in-training curve covers the rest.
- Procedural curve: magnitudes 0.1, 0.3, 0.5, 0.6 on the canonical states with shift seed 1000+, 100 episodes each, for the frozen prior (gate B) and the final checkpoint.

The frozen prior is evaluated on all four protocols before training starts, so every residual number has its baseline beside it.

The recipe bounds the residual through the BC penalty (β = `bc_loss_weight: 50`, the released Square image value, on the squared residual, relaxed only by the soft Q filter), so the correction a shifted start can receive is limited by the critic's action gradient relative to β rather than by any explicit clip. The released code already logs `residual_norm` and `q_filtering_active`; the record's sweep table carries both beside the shift magnitude, so a penalty that binds (residual norm flat while the held-out number stalls at the larger magnitudes) is visible and the documented levers are β (the paper ablates 50, 100, 150) and the deferred magnitude bound.
